## 一、做了什么

### 承诺

| 功能 | 怎么做的 |
|---|---|
| **登记** | 模型用 `commitment_create(要做的事, 时间)` 登记，用 `commitment_list` 查看，用 `commitment_cancel` 取消。运行规则里加了一句，告诉它答应了将来的事要登记 |
| **时间说法** | 能听懂"下午三点""三点半""明早""今晚""半小时后""一个半小时后""周五晚上""下周一早上九点""20号晚上"等，也能听懂具体时间（2026-10-07T09:00）。说"起床后""一睁眼""下班后""放学后"时，按作息表换算 |
| **兜底** | 每轮结束后，网关检查 bot 真正发出去的话里有没有"许诺未来"，比如"三点提醒你""明早叫你""晚点告诉你"。这一轮模型没登记时：时间能换算的，网关替它登记，下一轮告诉它"已替你登记，不是承诺就取消"；时间说得含糊的，下一轮提醒它自己登记。同一句话只提醒一次 |
| **到点** | 网关每 30 秒检查一次。到点就给模型一条系统说明："你答应过……约定的是几点"，由它按自己的性子开口 |
| **睡觉顺延** | 到点时她按作息在睡觉，就顺延到起床后再提醒，提示里写明晚了多久、那会儿在睡觉 |
| **兑现判定** | 以那一轮有没有真正送达的消息为准。没开口不算，5 分钟、15 分钟后各再提醒一次；3 次都没开口就标记失败，并通知你 |

### 主动消息

| 功能 | 怎么做的 |
|---|---|
| **按原因安排下一次** | 旧版先把下次时间随机重抽、再判断发不发，被跳过的机会就白白丢了。现在只有真正投出去之后才重抽随机间隔（30 分钟到 24 小时）。被跳过时按原因定下次：她在睡觉，起床后再试；对方大概率在睡，1.5–2.5 小时后；刚聊过、刚说过、正忙，30–60 分钟后；没素材，1–2 小时后 |
| **投递** | 新系统的 bot 投到网关的本机接口，带口令，写成账本里的一条系统消息，模型在下一轮处理。旧系统的 bot 照旧走旧流程 |
| **发朋友圈不再取消私聊** | 两边各走各的闸门 |
| **配额** | 新系统的 bot 走 DeepSeek，不占 Claude 订阅的 5 小时配额 |

### 心情与好感

| 功能 | 怎么做的 |
|---|---|
| **关系提示** | 也就是 `relationship.json` 里的 `prompt_snippet`（好感、信任等数值翻成的话）。旧系统每条私聊都带一遍；现在只在新会话开头和数值变化时带，省 token |
| **此刻在干什么** | 学期状态加上正在做的事，比如"在图书馆"。同样只在新会话开头和变化时带 |
| **被晾追问** | 判定逻辑和它的测试从旧调度器原样搬来，没有改动。追问写成账本里的系统消息；被晾后迟到的反应，在对方下一条消息时带一次 |
| **积温情绪** | `jiwen/tick.py` 对新系统的 bot 改读账本，包括对方说的和 bot 真正发出去的话。密钥沿用 `~/.dsh-bot/credentials.yaml`。调用失败后退避：10 分钟起，每次翻倍，最长 6 小时。旧版是每 5 分钟无限重试 |
| **作息** | 复用 `hang_situation.py`，新增 `--plan`，给出接下来几次起床的时刻和手上的事几点忙完 |
| **旧配置** | 新配置里加一行 `life_config: <旧配置文件>`，作息、生活、情绪等设置就从旧配置读；新配置里写了的键优先 |

## 三、要注意的

- **升级后每个会话会换一次段。** 运行规则里加了承诺那一句，系统提示词变了。按 M2 的规则，旧会话写完交接摘要就换新会话，这是正常的。
- **作息设置要从旧配置读。** 新配置里没有 `life_config` 这一行时，网关查不到作息：承诺照常提醒，但不会按睡觉顺延；"此刻在干什么"不带；被晾追问不触发。
- **主动消息、积温情绪还是定时任务。** 它们和旧系统一样由 launchd 定时跑，M6 会把定时任务切到新系统。这一期真机测试时手动跑。
- **"他"字。** 被晾提示的文案原样搬来，里面用"他"称呼对方，没有改。

## 四、真机清单（用 bot5）

本机 AI 的完整任务书在 `docs/dsh-migration/LOCAL-AGENT-M3.md`，下面是要点：

1. 在 `~/.dsh-bot/configs/bot5.yml` 里加 `life_config: <bot5 的旧配置文件>`。
2. 对 bot 说"5 分钟后提醒我喝水"，到点它应该主动来提醒。
3. 关系提示和此刻状态：只看日志里 `life.lines` 的几个"有/没有"。
4. 手动跑一次主动消息，看它是投出去了，还是按原因安排了下一次。
5. 手动跑一次积温情绪，看关系数值有没有更新（只看更新时间，不看数值内容）。
6. 可选：晚上睡前设一个提醒，第二天看它醒来后有没有补上。
