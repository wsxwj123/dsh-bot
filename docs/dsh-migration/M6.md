# M6：切换

## 结论

- 正式切换要用的东西都齐了：
  - 迁移：`setup.ts bot` 复制人设、配置、记忆、关系数值（M1 起就有）；新加的 `import_history.py` 导入旧私聊记录和还没到点的承诺；
  - 开机自启：`autostart.ts` 管网关、导演、主动消息，以及全部切完以后接手的共用服务；
  - 手册：`docs/dsh-migration/CUTOVER.md`，包括逐个 bot 切换、全部切完以后、回滚、故障排查表、dsh 升级。
- 旧承诺按你的决定，只迁还没到点、也没完成的。
- 测试数量：网关 223 项（通过 218，跳过 5）；Python 42 项（比 M5 多 3 项）。新增的有：导入后网关用旧记录补写摘要的端到端测试、导入脚本的测试、开机自启配置的测试、日志轮转的测试。
- 真机验收还没做，任务书在 `docs/dsh-migration/LOCAL-AGENT-M6.md`。主要是把 bot5 改成开机自启、演练一次回滚、对另一个 bot 只做导入的"试算"。正式切换哪几个 bot、什么时候切，由你定。

## 一、做了什么

| 功能 | 怎么做的 |
|---|---|
| **导入旧私聊** | `scripts/import_history.py`：从旧的 Claude Code 会话文件里取出你说的话和 bot 真正发出去的话（调用了 reply 的），只取和你私聊的、最近 30 天的。写进账本里一个"已结束"的段，新网关第一次处理这个私聊时会用它补写一份摘要，和崩溃恢复走同一条路。这个私聊在新系统里已经聊过的就不导，免得新旧交错。只读旧文件，只打印条数 |
| **导入旧承诺** | 同一个脚本读旧频道目录的 `.promises.json`，只导还没到点、也没完成的，来源记为 `import`，到点照常提醒。旧文件的格式没有文档，脚本按常见的字段名宽松识别；`--inspect-promises` 只打印字段名和类型，先看清楚再导 |
| **开机自启** | `gateway/scripts/autostart.ts` 生成 macOS 的 LaunchAgent：网关、导演常驻，退出了 10 秒后自动拉起；主动消息每 10 分钟看一次；情绪每 5 分钟；记忆整理每周日 4 点；朋友圈网页、电话常驻（后四项全部切完以后再装）。进程环境只放必要的几项（PATH、HOME、代理、关遥测），不放任何密钥 |
| **日志** | 网关、导演、Python 周边都写自己的日志，按大小轮转（5MB × 3 份）。launchd 的输出文件只有崩溃时的几行。实时看：`logs.ts -f`，或者 `tail -f ~/.dsh-bot/logs/<任务名>.log` |

## 二、真机清单

见 `docs/dsh-migration/LOCAL-AGENT-M6.md`。要点：

1. bot5 改成开机自启；杀掉它的网关进程，10 秒内自动拉起；
2. 主动消息的定时任务跑起来，日志里有跳过原因和下次机会；
3. 回滚演练（可选，要重启旧 bot，先问你）；
4. 对一个还没迁的旧 bot，只做导入的试算和承诺文件的结构检查，不写任何东西。
