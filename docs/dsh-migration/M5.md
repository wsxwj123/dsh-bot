# M5：多个 bot 与群聊

## 结论

- 按你的决定，群聊只做"导演点名"这一种：导演决定这一轮谁说话，同一时间只有一个 bot 开口；没人说话时导演也能自己开场。各 bot 自己判断、互相转发的那一套不做了。
- 群聊和私聊是分开的两个会话，私聊时会带一小段"群里近况"（也是你选的），bot 能接上话，又不会把群里的话整段塞进私聊。
- 方案第五节的 M5 自动化验收都通过了：
  - 两个网关加一个假 Telegram 群，群消息只记一次、不直接触发回复；导演点名后才说话，说的话进群聊记录；
  - 被点名的 bot 能看到别的 bot 刚说的话；
  - "闭嘴"锁、接话额度都生效；
  - 群里的话不进私聊会话，私聊只带一次近况；
  - 点名要口令，没有口令会被拒。
- 测试数量：网关 220 项（通过 215，跳过 5）；Python 39 项（比 M4 多 5 项）。
- 真机验收还没做，任务书在 `docs/dsh-migration/LOCAL-AGENT-M5.md`。要用两个新系统的 bot，所以除了 bot5 还要再迁一个。

## 一、做了什么

| 功能 | 怎么做的 |
|---|---|
| **群消息** | 网关收到群消息（群要写在 `access.json` 的 `groups` 里），只记进群聊记录，不直接回复。几个网关都会收到同一条，用一个抢占标记保证只记一次。群里点名本 bot 的命令（`/clear@本bot` 等）照常处理 |
| **群聊记录** | 所有新系统的 bot 共用一份：`~/.dsh-bot/groups/<群 id>.jsonl`，格式和旧系统的 `group_transcripts` 一样。bot 自己在群里说的话由它自己的网关记下。Telegram 不把 bot 的消息投给别的 bot，旧系统为此要 bot 之间互相转发（不带口令）；现在直接记进共用文件，不再需要转发 |
| **导演** | 还是原来的 `director.py`，改了三处：① bot 名单从注册表读（配置 + 网关启动时写的 `state/bot.json` + `access.json` 里的群），不再写死 bot1–3；② 点名改走网关的本机接口（带口令），网关写进账本、开一轮；③ 调模型失败时退避：5 秒起翻倍，最长 10 分钟。旧版是每 2 秒再试一次，没有尽头。"闭嘴"锁、接话额度、自主开场的各种节流都照旧 |
| **"正在私聊"** | 网关每收到一条私聊，写一个"刚聊过"标记（格式同旧系统），导演据此不点正在私聊的 bot 去群里说话 |
| **群里近况** | 私聊时，如果这个 bot 在的群里上次之后有人说话，就附一段近况：最多 8 句、只看 12 小时内，你的话记作"对方"，它自己的话记作"你"。每个私聊记到哪一句，同样的话不会带第二次 |
| **群里不做的事** | 承诺登记、被晾追问、关系和作息提示只在私聊里做 |
| **多个 bot** | `setup.ts bot` 给新 bot 自动分配一个没用过的本机接口端口（17950、17951……）。导演用的显示名取配置里的 `display_name` |

## 二、怎么用

1. 群写进每个参加的 bot 的 `access.json`：`"groups": {"<群 id>": {"allowFrom": []}}`。`allowFrom` 留空表示群里谁说话都记；写了就只记这些人。
2. 打开导演开关：建一个空文件 `~/.dsh-bot/director/mode/<群 id>`。删掉就关。
3. 启动导演：`HUB_CONFIGS_DIR=~/.dsh-bot/configs DIRECTOR_CHAT_ID=<群 id> python3 director.py --run`。启动时会打印它认出的 bot 名单。
4. bot 在 BotFather 里要关掉隐私模式（`/setprivacy` → Disable），不然收不到群里的普通消息。旧系统里在群里用过的 bot 本来就是关着的。

导演用的模型和旧系统一样走 DeepSeek，密钥用新系统的 `~/.dsh-bot/credentials.yaml`，不用另配。

## 三、要注意的

- 切换期间，旧系统的导演和旧 bot 还在用旧的群聊记录。新系统的 bot 最好先在一个新建的测试群里试，别和旧 bot 混在同一个群。
- 群聊记录是本机文件，里面有群里的聊天内容，权限跟着 `~/.dsh-bot` 走（只有你自己能读）。
