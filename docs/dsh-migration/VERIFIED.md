# dsh 实测核对记录

- 日期：2026-10-05
- 环境：Linux 容器，bun 1.3.14，node 22
- 方法：每项都在新建的隔离目录里跑（独立 HOME、独立 DSH_HOME），用本机假模型服务代替 DeepSeek，记录 dsh 实际发出的每个请求。全程不需要密钥。
- 复现：`DSH=<dsh 路径> bun lab/dsh/offline/facts.ts`（21 项，约 3–5 分钟），说明见 `lab/dsh/README.md`

测试了两个版本：

| 版本 | 怎么装的 | 备注 |
|---|---|---|
| 0.1.5-rc.1 | `npm install @deepseek-ai/dsh@0.1.5-rc.1` | **230 个子包实际装到的是 0.1.5-rc.3**。你机器上是 rc.2。主包依赖写的是 `^0.1.5-rc.1`，所以今天重装会拿到更新的子包 |
| 0.2.0-rc.2 | `npm install @deepseek-ai/dsh@0.2.0-rc.2` | npm 上当前的 `latest`。和你的桌面版是同一代（会话格式 v4） |

结论先说：

- 两个版本在新系统要依赖的行为上一致：ACP 会话、按会话选模型、续接、取消、HTTP MCP 工具、"只留人设"配置。
- 差别有四处，都在"发往 DeepSeek 的请求"和"挂 MCP 时自动加的东西"上，见第二节。

## 二、两个版本的差别

| 项目 | 0.1.5 | 0.2.0 | 对新系统的影响 |
|---|---|---|---|
| 发往 DeepSeek 的协议 | Chat Completions | Anthropic Messages（`/anthropic`） | 我们不直接碰，dsh 自己处理。用量字段的名字不同，验证脚本两种都认 |
| 会话日志上传（`dsh_session_log`） | 默认关 | **默认开**，每个请求都带上会话事件增量，含对话原文 | **必须禁用 `session-log-deepseek` 行。**`DSH_TELEMETRY_DISABLED` 只关得掉遥测，关不掉这个 |
| 挂 MCP 时自动加的东西 | 无 | 3 个资源工具，外加系统提示词末尾一段 | 必须禁用 `mcp-resources` 行，否则人设后面会多出一段英文，而且多费 token |
| 调用工具后模型回空文本 | 当作"空回复"自动重试一次（每轮多一次请求） | 不重试 | 运行规则要引导模型调用 reply 之后给一个极短的收尾。真模型会不会回空，由 real-03 的"每轮请求数"判断 |

## 三、速查表以外的新发现

1. **失败、取消、崩溃之后，用户消息都留在 dsh 的历史里**（C13–C15）。
   - 旧系统"把在飞消息放回队列、原样重发"的做法，搬到 dsh 上会让模型看到重复消息。
   - 新系统的处理方式见方案 3.3：dsh 还活着时，发一句"补救提示"而不是原文；dsh 进程死了，就换新会话，用账本重建上下文。
2. **dsh 估 token 有两个口径，压缩用的是两个口径的混合**（C21，读源码确认）。
   - 判断"超没超阈值"时，用的总量会对齐供应商回报的用量。这个总量就是 ACP 回报的 `usage_update.used`，假模型下两者每轮只差约 10 个 token。
   - 计算"保留最近多少原文"时，按每条消息"4 个字符 1 个 token"估（源码里是 `CHARS_PER_TOKEN = 4`，两个版本都是）。中文会被低估好几倍。
   - 结果：保留量设大了，dsh 认为全部对话都在保留区里，一直不压，上下文继续涨；设小了，压完还是超阈值，几乎每轮都压。
   - 这是不用出厂压缩的硬证据之一。好消息是 `usage_update.used` 本身是准的，可以直接拿来控制我们自己的预算。
3. **思考内容会回传**（C16，两个版本都是）。
   - 0.2.0 的说明文件原话是"此前 assistant 轮次的推理内容会原样传回"。
   - 会不会按输入计费，要用真密钥测，见 real-02。
4. **模板变量**：`{{user}}` 报错时，dsh 列出的已注册变量是 `provider, mode`，和速查表写的 `model, cwd` 不一致。不影响结论：人设里出现 `{{` 都要转义。
5. **会话 id 不能指定，续接必须同一个 cwd。** 新系统要自己存"聊天 → 当前 dsh 会话 id"的对应关系，并且固定每个 bot 的 cwd。
6. **版本号相同不等于代码相同。** 主包依赖是 `^` 范围，重装时子包会漂移。新系统要用锁文件钉死整棵依赖树。
7. **会话中途换模型，dsh 会往历史里插一条英文说明**（M1 开发时在 0.2.0-rc.2 上发现）。
   - 内容是 `[model changed: assistant turns above this point were generated by X; the session continues with Y]`，以用户消息的身份放在那一轮用户消息后面。
   - 只在真的换模型那一轮出现一次，几十个 token。对聊天没有影响，记录在案。
   - 自动化测试 `gateway/test/e2e/real-dsh.test.ts` 会断言它存在，dsh 升级时如果行为变了能马上发现。
