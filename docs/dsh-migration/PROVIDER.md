# 新建供应商：/provider add

## 怎么用

主人在和**任意一个**新系统 bot 的**私聊**里发：

```
/provider add <名字> <接口地址> <密钥> [openai|anthropic]
```

- 末尾写 `openai`：对方是 OpenAI 兼容接口（地址一般以 `/v1` 结尾，比如 `https://openrouter.ai/api/v1`）。
- 不写：按 Anthropic 接口处理（地址写到 `/v1` 之前，比如 `https://api.anthropic.com`，或者本机 provider-proxy 的地址）。
- 名字只能用英文字母、数字、`-`、`_`，以字母或数字开头，最多 32 个字符。大小写随意，`/provider MyProxy` 和 `/provider myproxy` 是同一个。

bot 收到后：

1. 马上删掉这条消息。删掉了会说"已经删掉了"；没删掉会提醒你手动删。
2. 把密钥写进凭据文件，登记这个供应商，再去对方接口拉模型列表。
3. 回复"已添加供应商「X」，拉到 N 个模型。切过去：/provider X"。
   - 模型列表没拉到：供应商照样建好，回复里写明原因（比如密钥不对、地址不对、对方没有模型列表）。之后在管理台的模型页点"刷新模型列表"，或者发 `/provider refresh X`。
   - 同名的再发一次 add，就是更新地址、密钥，并重新拉列表。

相关命令：

| 命令 | 作用 |
|---|---|
| `/provider` | 列出所有供应商、密钥配没配；模型列表没拉到的单独列出来 |
| `/provider X` | 换到 X 的第一个模型（`/model X/<模型>` 指定模型）；`/model default` 换回配置文件里的 |
| `/provider refresh X` | 重新拉 X 的模型列表。没拉到时沿用上次的列表，已经能用的不会消失 |
| `/provider remove X` | 删掉 X 和它的密钥。正在用它的 bot 换回配置文件里的模型 |

## 三件事说清楚

**1. "面板"是哪个：新系统管理台的模型页（`/hub/dsh-model`），不是旧管理台的供应商页。**

- 旧管理台的供应商页（`/hub/provider`）管的是旧系统 Claude Code 的设置和 cliproxy，新系统的 bot 不读它。
- 新系统的模型页原来就能给每个新 bot 换模型。这次加了一块"用 /provider add 建的供应商"：列出名字、接口类型、模型数、上次拉列表的结果，每个供应商有一个"刷新模型列表"按钮。
- 新建也能在页面上做，密钥只收不显、不落日志，列表上只看得到「已配密钥 / 缺密钥」。录密钥建议用 127.0.0.1 打开页面，走隧道（cloudflare tunnel 之类）等于把密钥交给隧道提供方。

**2. dsh 怎么登记自定义供应商。**

- dsh 的 `llm-pi-ai` 插件按"路由"登记供应商。每条路由要写：
  - 协议（`anthropic-messages` 或 `openai-completions`）；
  - 接口地址；
  - 至少一个模型；
  - 密钥的键名（`apiKeyEnv`）。
- 密钥本身不写在路由里。dsh 每次发请求时，按键名去凭据文件（`~/.dsh-bot/credentials.yaml`）里取。
- 网关原来就会把配置文件里的 `brain.routes` 写进 dsh 的补丁层。这次多读一个共用的登记文件 `~/.dsh-bot/providers.json`，把里面的供应商也并进去。
  - 登记文件里有名字、协议、地址、密钥的键名（`PROVIDER_<名字>_API_KEY`）、模型列表，**没有密钥**。
  - 配置文件里有同名路由时，以配置文件为准；所以 add 会拒绝和本 bot 配置文件里路由重名的名字。
  - 模型列表是空的供应商不并进去（dsh 要求至少一个模型），等刷新拉到了再并。
- 拉模型列表的方式和 dsh 自己一样：
  - OpenAI 兼容：`GET <地址>/models`，带 `Authorization: Bearer`；
  - Anthropic：`GET <地址>/v1/models`，带 `x-api-key`（地址末尾有没有 `/v1` 都行）。
  - 列表里写了上下文窗口的照用；没写的按 131072 算（dsh 的默认值是 262144，很多模型没那么大，按小的算，换段早一点，不会因为超长而报错）。

**3. 几个 bot 共用时怎么生效、要不要重启。**

- 登记文件和凭据文件都在 `~/.dsh-bot` 下，所有新系统 bot 共用，**在哪个 bot 上加都一样**。
- 不用重启网关。每个网关本来就定时检查配置文件有没有改；现在连登记文件一起检查。发现路由变了，等这个 bot 手上没有正在进行的回合时，重启一次它的 dsh 进程（几秒钟，和改人设后一样），聊天接着原来的会话。
  - 收到命令的那个 bot 会先重启完再回话，所以回复里的"切过去"马上就能用。
  - 别的 bot 在几秒内跟上；如果它正在聊，等这一轮结束。这时发 `/provider X` 会提示"刚加上，稍后再试"。
- 换到新供应商只影响你切换的那个 bot。别的 bot 只是"能切"，不会自动切过去。

## 安全

| 要求 | 怎么做的 |
|---|---|
| 只有主人能用 | 不是主人、或者不在私聊里：什么都不做，照样删消息，回一句"只有主人在私聊里能用"。在群里发的，还会建议去供应商那里换掉密钥 |
| 写进账本之前拦下 | 收消息时，在过完白名单、写账本之前就认出 `/provider add`，只推进 Telegram 的消息序号，不写账本、不写 chat.log、不进群聊记录、不打"已读"表情，也不交给模型 |
| 密钥只进凭据文件 | 只写进 `~/.dsh-bot/credentials.yaml` 的 `refs` 下一个键。写之前读回校验，原有内容和注释原样保留；先写临时文件再改名，权限保持 600 |
| 回复和日志里只有名字和数量 | 日志只记供应商名字、协议、模型数和成功与否。拉列表失败只写状态码这类原因，不带对方的回包（有的接口会把密钥原样回显）。另外这个密钥一收到就登记进日志的脱敏表，万一哪里带上了也会被换成 `***` |

自动化测试（`gateway/test/acceptance/provider_add_cmd.test.ts` 与 `gateway/test/acceptance/provider_secret.test.ts`）用假 Telegram 和假供应商接口跑一遍，然后在下面这些地方逐个找密钥，都找不到：
- 账本（含 WAL）；
- gateway.log、chat.log；
- dsh 的会话和补丁层；
- 模型收到的全部内容；
- 登记文件；
- 发出去的所有消息。

`report.ts` 的最后一节也改成同时查日志、账本、补丁层和登记文件，真机上可以用它自查，不用打开凭据文件。
