# M4：语音、生图、朋友圈、管理台

## 结论

- 这一期做完的内容：
  - 语音：收语音转成文字给模型；模型可以选择用语音回复，由网关合成后发出；
  - 图片：对方发的图附给模型看；模型看不了图时，改成一句说明，不会卡住；
  - 生图：模型自己写画面描述、网关替它跑原来的生图脚本，生成好的图用 reply 发出；
  - 朋友圈：看最近的圈、点赞、评论、发圈、配图、删评论；网页上的评论和新圈通知能送到新系统的 bot；
  - 电话：挂断后的回顾里有双方的话；电话里答应的事登记成承诺（M3 挪过来的那一条）；
  - 管理台：新加"新系统模型"页面，可以给新系统的 bot 换模型。
- 方案第五节的 M4 自动化验收全部通过：
  - 每条链路都用假服务端到端跑通（假 Telegram、假 voice-bridge、假生图脚本、假网关）；
  - 别的 bot 的私密圈不会出现在查询结果里；
  - 日志和命令行里没有令牌：NovelAI 令牌只通过环境变量交给生图脚本，Telegram 令牌不交给 voice-bridge。
- 测试数量：
  - 网关 217 项（通过 212，跳过 5），比 M3 多 16 项；
  - 真 dsh 5 项；
  - Python 34 项，比 M3 多 5 项。
- bot5 真机验收（报告在 `docs/dsh-migration/local/reports/m4-check.md`）：看图、网页评论、管理台换模型符合。收语音、发语音、发圈不符合；自拍能出图，但同一张图发了两遍，而且很慢。报告里的 8 个问题都已修好，见第五节，其中 5 项需要补测。

## 一、做了什么

| 功能 | 怎么做的 |
|---|---|
| **收语音** | 网关把语音下载到 bot 自己的媒体目录，把文件路径交给 voice-bridge 转写。模型看到的是"[语音] 转写的文字"。转不成文字时，模型会被告知"没听清这条语音，照实告诉对方"，聊天照常进行 |
| **发语音** | 和旧系统一样：reply 带 `as_voice` 时，每段先发文字，再发这一段的语音。`voice_text` 是朗读稿（比如人设里写的"中文文字配日语语音"），按段对应；不写就读文字本身。另有 `voice_emotion`（语气）、`voice_instruct`（说话方式）。频道目录的 `access.json` 里没有 `voiceId` 时只发文字 |
| **收图片** | 图片附在这一轮的消息里给模型看。模型不支持看图时，dsh 会拒收整条消息；网关这时去掉图片、加一句"看不到图片内容"再发一次，并记住这个模型看不了图 |
| **生图** | 两个新工具：`image_guide` 给出原来生图技能的写法说明，`generate_image` 接收模型写好的画面描述。网关替模型跑原来的生图脚本（NovelAI 或 ComfyUI，脚本没改）。10 秒内生成好，就直接返回图片路径；没生成好，先告诉模型"还在生成"，好了以后再用一条系统消息告诉它 |
| **朋友圈** | 新工具 `moments` 有 6 个动作：recent（看最近的圈）、like（点赞）、reply（评论）、post（发圈）、set_image（配图）、delete_comment（删评论）。网关替模型跑原来的朋友圈脚本，脚本没改。查别的 bot 的圈时，不列它的私密圈 |
| **朋友圈通知** | 用户在网页上评论 bot 的圈、或者发了新圈，原来是往 bot 的 inbox 里写一条让 Bash 执行的命令。现在新系统的 bot 改成投到网关，命令换成工具用法。旧系统的 bot 照旧 |
| **电话** | 挂断后的回顾改为双方的话都带上（原来只有用户说的），投给网关。网关从 bot 在电话里说的话中找许诺，登记成承诺，来源记为 `call`。同一通电话重复投递，只登记一次 |
| **主动消息、通话插话** | `self_initiate.py` 和电话里的插话都改走同一个投递模块 `gateway_client.py` |
| **管理台换模型** | 管理台新加"新系统模型"页面（`/hub/dsh-model`），和 Telegram 里发 `/model` 是同一套逻辑。网关新加本机接口 `/v1/model`，要口令、只听回环地址。管理台原有的登录检查照样管这个页面 |
| **旧名字** | 朋友圈记录和画风绑定用的是 bot 在旧系统里的名字。新配置里写了 `life_config` 的，就自动取那个旧配置文件的文件名；也可以用 `life_id` 直接写。生图、朋友圈都按旧名字来，朋友圈脚本也能用旧名字找到新配置，网页上显示的名字和头像也照旧 |
| **本机检查** | `setup.ts check` 多了几项：音色、voice-bridge、生图说明和令牌、朋友圈库。没配不算问题，只提示哪个功能用不了；不显示任何密钥 |
| **voice-bridge 日志** | 关掉 httpx 每次请求的日志；新网关的媒体目录（`~/.dsh-bot`）加进允许读取的目录 |

## 二、需要你准备的

| 项 | 说明 |
|---|---|
| voice-bridge | 用旧系统已经在跑的那个就行（默认 `127.0.0.1:7788`）。如果它设了 `VOICE_BRIDGE_TOKEN`，在凭据文件的 `refs` 里加一项同名的值 |
| 音色 | 在新频道目录的 `access.json` 里加 `voiceId`，值和旧频道目录 `access.json` 里的一样 |
| 生图 | 在 bot 配置的 `gateway` 下加 `image_skill_dir: ~/.claude/skills/novelai-skill`（你本机原来那份技能目录，它的 `.env.local` 里已经有 NovelAI 令牌）。不想用 `.env.local`，也可以在凭据文件的 `refs` 里加 `NOVELAI_BEARER_TOKEN`。用 ComfyUI 的话写 `image_provider: comfyui` |
| 朋友圈 | 在 `gateway` 下加 `botlife_db: <旧仓库>/state.db`，新旧系统共用一个朋友圈库 |

## 三、要注意的

- 运行规则加了一句（生图和朋友圈），所以升级后每个聊天的第一条消息会换一次段。这是正常的。
- 发圈的文案仍由原来的朋友圈脚本生成，生成方式没动。
- 切换期间，旧的朋友圈网页（8765 端口）上的评论只会送到旧系统的 bot。要让新系统的 bot 收到通知，得用新仓库启动的网页，任务书里用 8767 端口单独起一个。M6 切换时再换掉旧网页。
- 生图如果超过 45 秒，模型会先回一句"等我一下"之类的话，图好了再发。

## 四、真机清单

本机 AI 的任务书在 `docs/dsh-migration/LOCAL-AGENT-M4.md`。要点：

1. 发语音给 bot，bot 能听懂；请 bot 用语音回复，能收到语音。
2. 发一张图给 bot，bot 能说出图里有什么（或者说看不到图）。
3. 让 bot 发一张自拍。
4. 在网页上评论 bot 的朋友圈，bot 会回复；让 bot 发一条朋友圈。
5. 在管理台给 bot5 换一次模型，再换回来。
6. （可选）给 bot 打一个电话，电话里让它答应一件事，挂断后看承诺表。

## 五、真机验收和修改

真机报告列了 8 个问题，修改如下：

| 问题 | 原因 | 修改 |
|---|---|---|
| 1. 收语音都没转成文字 | 正在跑的是旧的 voice-bridge，它只读白名单里的目录，不认 `~/.dsh-bot`，返回 403 | 遇到 403，网关把语音临时复制到生图目录（`~/resource/media`，旧白名单里有）再转一次，转完马上删。转不成时告诉模型"没听清，照实告诉对方"，免得它装作听懂了。不用改旧系统 |
| 2. 发语音是中文、没有文字 | 新的 reply 少了旧系统的 `voice_text`（朗读稿） | 补上 `voice_text`，做法和旧系统一样：每段先发文字，再发朗读稿合成的语音。人设里的语音规则不用改 |
| 3. 同一张图发了两遍 | dsh 等一次工具调用最多 60 秒，这个上限不能从外面改。带两张图的 reply 要发 60–75 秒，dsh 判超时，模型以为没发出去，又调一次 | 两处都改了：① reply 发了 45 秒还没发完，就先告诉模型"在发了，不要重发"，后台接着发，这一轮等发完才收尾；② 同一轮里同一个文件只发一次 |
| 4. 发一张图要 26–45 秒 | 原图是 2MB 左右的 PNG，经代理上传慢 | 在 Mac 上用系统自带的 `sips` 把超过 1MB 的 PNG 转成 JPEG 再发（Telegram 收到照片本来也会压成 JPEG），原图不动。日志里会出现 `send.photo_shrunk`，带前后大小 |
| 5. 生图那一轮先干等 45 秒 | 7 次生图都超过 45 秒，等满了也拿不到图 | 只等 10 秒。没好就先让模型回话，好了再通知它 |
| 6. 发朋友圈被"睡觉"挡住，报错原因也不对 | 发圈前的检查第一条是"睡觉不发"；用户主动要求时没放开这一条。脚本最后一行是笼统的"没生成" | 用户在聊天里要她发圈时，作息上的"睡觉/上课"不拦。没发成时，把真正的原因（比如 `sleeping`）告诉模型并记进日志，提示马上重试也一样 |
| 7. 停网关后还在发消息，dsh 退出记成意外 | Ctrl+C 时 dsh 和网关同时收到信号；正在发的 reply 不知道网关要停 | 一开始停就不再发还没开始的段（日志 `send.halted`）。dsh 这时退出算正常，记 info |
| 8. 文档里端口写错 | — | 第三节改成 8767 |

用户提的"想像 tmux 那样实时看日志"，放到 M6 做开机自启时一起做。

### 补测（本机 AI 按任务书的第 3、4 步启动，只测这几项）

| 项 | 怎么做 | 预期 |
|---|---|---|
| a. 收语音 | 发一条语音 | 出现 `media.transcribe_retry` 和 `media.prepared`（`transcribed` 是 true），bot 的回复对得上。`~/resource/media/dsh-bot-voice/` 是空的 |
| b. 发语音 | 让 bot 用语音回复 | 每段先收到文字，再收到语音；人设里要求日语语音的，语音是日语 |
| d. 自拍 | 让 bot 发两张自拍 | 每张图只收到一次。`tool.generate_image` 之后不再干等 45 秒。在 Mac 上出现 `send.photo_shrunk`，记下发一张图用了几秒 |
| f. 发朋友圈 | 在作息是"睡觉"的时段让 bot 发圈 | `tool.moments` 的 `action` 是 `post`，`code` 是 0，网页上多一条圈 |
| 停网关 | bot 正在发多段回复时按 Ctrl+C | 出现 `send.halted`；`dsh.exited` 是 info 级，`unexpected` 是 false |
