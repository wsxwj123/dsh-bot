# M2：记忆

## 结论

- 记忆这一期做完了：
  - 会话按预算换段；
  - 换段时在旧会话里写交接摘要，写摘要这一轮锁住所有工具；
  - 新会话开头带上长期记忆、最近一份摘要和最近的原话；
  - 模型可以用 `remember` 工具记事；
  - Python 周边改读账本。
- 方案第五节列的 M2 自动化验收（6 条）全部通过。网关现在一共 82 项测试，Python 读账本的测试 10 项。真 dsh 加假模型也跑通了换段。
- 需要你在自己机器上做的：按第四节的真机清单，用 bot5 聊到换段，确认它不失忆。本机 AI 的任务书在 `docs/dsh-migration/LOCAL-AGENT-M2.md`。

## 一、做了什么

| 功能 | 怎么做的 |
|---|---|
| **预算** | 默认是模型上下文窗口 × 80%，窗口大小由 dsh 回报。配置里写了 `brain.max_input_tokens`，就取两者里小的那个 |
| **什么时候换段** | 每轮结束后看用量，到线就趁这个聊天还空着马上换段，下一条消息不用等摘要。新消息一进来就会超预算时，先换段再处理。一段里至少聊过两轮才会换，防止预算比"新会话开头"还小时每轮都换 |
| **写交接摘要** | 在旧会话里写，几乎全部命中缓存。这一轮所有工具都锁住，模型就算想调工具也发不出去。摘要用五个小标题：我说过的要紧话 / 我答应过的事 / 对方的情况 / 正在聊的话题 / 我们现在的关系和气氛 |
| **摘要写不成** | 旧会话里写失败时，把这一段的账本流水交给一个不带任何工具的临时会话补写。摘要为空或不像样（太短、小标题缺太多）时不保存，新会话开头沿用上一份 |
| **崩溃以后** | 旧会话已经用不了，先用账本流水补写这一段的摘要，再开新会话。还没处理完、要重新送的消息不会写进摘要，保证它只出现一次 |
| **新会话开头** | 依次是：长期记忆、最近一份摘要、最近原话（对方说的和 bot 真正发出去的，默认上限约 1.2 万字）、"上一条回复被中断"的说明（如果有）、一句"新会话开始"的提醒。这些和新消息分成两个内容块发送 |
| **`/clear`** | 当前这段先写一份摘要，然后开新会话。新会话里不再带清空前的原话，但带着摘要和长期记忆，和旧系统 clear_summary 的做法一致。摘要为空时不覆盖上一份 |
| **`remember` 工具** | 模型把值得长期记住的事追加到 `MEMORY.md` 的"随手记"一节，同样的内容不重复记。别的聊天在下一轮会收到一行提醒：你在别的聊天里新记下了什么 |
| **长期记忆放哪** | `<频道目录>/memory/MEMORY.md`，同目录下的主题记忆文件也一起带上，默认上限 2 万字。旧系统里 bot 真正在用的记忆在 Claude Code 的目录里，`setup.ts bot` 第一次准备时会自动导过来，也可以用 `setup.ts memory` 再导一次 |
| **私聊、群聊各自的会话** | 每个聊天一个会话，前情也只从这个聊天的记录里取。群聊在 M5 接入 |
| **Python 读账本** | `chat_history.py` 的 6 个函数改读账本，函数名和返回格式都没变。找不到账本时（旧系统的 bot）照旧读 Claude Code 的会话文件 |
| **记忆整理任务** | `memory_compactor.py` 有以下改动：<br>- 对话材料从账本里取，含 bot 真正发出去的话；<br>- 新系统的 bot 直连 DeepSeek，密钥从 `~/.dsh-bot/credentials.yaml` 读，失败退避重试 2 次；<br>- 写回前先重读文件，整理期间新记下的条目不会被覆盖；<br>- 改成原子写入 |

## 三、这一期的新发现

- **Telegram 给的消息时间只精确到秒。** 同一秒里的一问一答如果按这个时间排序，bot 的话会全排在前面，补回原话的字数上限被它占满。现在补前情、写摘要的流水一律按本机记录的毫秒时间排序。这个问题是测试发现的，已修好。
- **预算很大时，换段很少发生。** 用 DeepSeek 时窗口是 100 万、预算 80 万，日常聊天几乎碰不到。想控制成本，就设 `brain.max_input_tokens`，比如 3 万到 5 万。

## 四、真机清单（用 bot5）

本机 AI 的完整任务书在 `docs/dsh-migration/LOCAL-AGENT-M2.md`，下面是要点：

1. 先停旧 bot5。
2. 导入旧系统的长期记忆：`bun gateway/scripts/setup.ts memory bot5 --from <bot5 的旧目录>`。
3. 为了在一两个小时里看到换段，临时在 `~/.dsh-bot/configs/bot5.yml` 的 `brain` 下加 `max_input_tokens: 30000`。bot5 的人设约 9 千 token，新会话开头大约再占 1 万多，所以聊二三十轮就会换一次。
4. 聊天时，先告诉它几件人设编不出来的具体事情（比如一个名字、一个日期），然后正常聊，直到 `gateway.log` 里出现 `segment.rolled`。
5. 换段之后问它前面那几件事，看它记不记得。
6. 让它"记住"一件事，看 `MEMORY.md` 是否多了一条（只数行数，不看内容）。
7. `/clear` 之后问一件清空前聊过的事：要点应该记得（来自摘要），原话细节可能记不全。
8. 测完把 `max_input_tokens` 删掉，或者改成你想要的成本上限。

另外，每轮的输入 token 在 `report.ts` 里能看到（"每轮上下文大小"）。缓存命中率网关看不到，请到 DeepSeek 控制台的用量页查看。

## 五、后面要你决定的

- **日常要不要设 `max_input_tokens`。** 不设，就按窗口的 80%，一个会话可以一直聊很久，单次请求最大可能到几十万 token（命中缓存的部分按缓存价计费）。设成 3 万到 5 万，单次请求的花费可控，代价是大约每二三十轮写一次摘要。
- **`/clear` 的效果。** 现在保留一份摘要，和旧系统一样。如果你希望 `/clear` 之后什么都不记得，告诉我，可以加一个 `/clear 全部`。
